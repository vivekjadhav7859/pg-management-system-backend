# AWS SES Production Access & Domain Verification Guide for GoBanqo

This guide provides step-by-step instructions for completing **Phase 2 (AWS Foundation)** of the GoBanqo notification platform setup.

---

## 1. Environment & Credentials Configuration

Ensure your deployment environment or Serverless environment has the appropriate AWS credentials set:

- **AWS Region**: `ap-south-1` (Asia Pacific - Mumbai)
- **Sender Domain**: `gobanqo.com`
- **Default System Sender**: `noreply@gobanqo.com`

---

## 2. Verify Domain Identity (`gobanqo.com`) in AWS SES

1. Log in to the [AWS Management Console](https://console.aws.amazon.com/ses/).
2. Select region **ap-south-1** (Mumbai).
3. In the left navigation pane under **Configuration**, click **Identities**.
4. Click **Create Identity**.
5. Select **Domain** and enter `gobanqo.com`.
6. Enable **Easy DKIM** (recommended by AWS).
7. Select **RSA_2048_BIT** for DKIM signing key length.
8. Click **Create Identity**.

---

## 3. Configure DNS Records (Route53 or Domain Provider)

Add the following DNS records generated by AWS SES into your domain registrar / DNS provider for `gobanqo.com`:

### A. DKIM CNAME Records (3 Records)
Add the 3 CNAME records generated by AWS SES:
- `[token1]._domainkey.gobanqo.com` -> `[token1].dkim.amazonses.com`
- `[token2]._domainkey.gobanqo.com` -> `[token2].dkim.amazonses.com`
- `[token3]._domainkey.gobanqo.com` -> `[token3].dkim.amazonses.com`

### B. SPF Record (TXT)
Add or update the TXT record on host `@` (or `gobanqo.com`):
```text
v=spf1 include:amazonses.com ~all
```

### C. DMARC Record (TXT)
Add a TXT record on host `_dmarc.gobanqo.com`:
```text
v=DMARC1; p=none; rua=mailto:dmarc-reports@gobanqo.com; pct=100
```

---

## 4. Request Production Access (Exit SES Sandbox)

By default, all AWS accounts start in **SES Sandbox Mode**, which limits sending to verified recipient email addresses only.

To enable sending emails to all tenants automatically:

1. In the AWS SES Console, navigate to the **Account Dashboard**.
2. Under **Sending Details**, locate the banner reading *"Your account is in the sandbox"*.
3. Click **Request Production Access**.
4. Fill out the request form:
   - **Mail Type**: `Transactional`
   - **Website URL**: `https://gobanqo.com`
   - **Use Case Description**:
     > *"GoBanqo is a PG and Hostel Management platform. We send transactional emails to tenants including monthly rent payment reminders, digital payment receipts, welcome emails on check-in, and tenant maintenance request alerts on behalf of property managers. We maintain strict opt-out compliance and unsubscribe mechanisms."*
   - **Additional Details**: State that all emails are triggered by explicit user actions or property management schedules.
5. Click **Submit Request**.
6. AWS support typically approves production requests within 24 hours.

---

## 5. Development Fallback Mechanism

In development mode (`STAGE=dev`), GoBanqo uses a transparent **Sandbox Fallback** in [sesProvider.js](file:///d:/GoBanqo-dev/pg-management-system-backend/src/providers/email/sesProvider.js). 

If AWS SES rejects an unverified dev test address with `MessageRejected: Email address is not verified`, the system automatically catches the error, logs a dev warning, and simulates delivery so dev/QA testing proceeds without disruption.
